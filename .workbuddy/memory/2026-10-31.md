## 00:15 曲目跨页续播 + 播放按钮间距（style.css?v=88 / bgm.js?v=5，提交 d1f051a）

- **问题**：多页静态站，点导航是真实文档跳转，STUDIO 里在放的歌会被浏览器掐断。
- **方案（非 SPA 的续播）**：
  - `studio.html` 播放器把「key / src / title / currentTime / 时间戳 at / playing」写进 `sessionStorage['ncj:track']`，写入时机：play、pause、playTrack、ended、pagehide、beforeunload，外加播放中每 2.5s 一次。
  - `bgm.js` 在**非 studio 页**（`document.querySelector('.music-page')` 为空）读这个 key：把本页的 `audio` 换成曲目 src（`loop=false`、`volume=1`），seek 到 `t + (now-at)/1000`（gap 上限 3s）后自动 play，导航栏三角按钮跟着变成曲目开关，title 显示曲名。
  - 切回 studio 时由播放器自己 `restoreSession()`：设 src → seek → play → `markActive` 高亮 + `setState('playing')`。
  - 6 分钟以上的旧状态不恢复（避免第二天刷新突然放歌）。
- **坑 1**：恢复播放时**不能**立刻 `startSpectrum()`。`createMediaElementSource()` 会把音频改道进 AudioContext，没有用户手势时 context 是 suspended → 直接没声音。解法：`noSpectrumUntil = Date.now()+4000`，`startSpectrum()` 开头拦；用户手动点播放时清零。代价是恢复后的前几秒没有频谱条。
- **坑 2**：`audio.currentTime = t` 是异步生效的，紧接着 `paint()` 读到的还是旧值 → 加 `seeked` 事件再刷一次。
- **现实限制**：浏览器自动播放策略下，无手势的新文档 `play()` 可能被拒（Safari/iOS 基本必拒），catch 里把按钮退回三角态，用户点一下从原位继续；真正的零断口只有 SPA 化才能做到，本次没做。
- **间距**：`.bgm-toggle` 原本只有 `margin-left:18px`，右边缘紧贴 HOME。加 `margin-right:20px`（窄屏 `@media(max-width:720px)` 里覆盖回 0，因为那时按钮被挪到导航栏第一格）。

## 01:55 「刀口」机制（archive.js?v=17，提交 9c28282）

用户反馈：整体回位慢了，但没有"刀切过的痕迹"。根因不是速度，而是**推开模型**——原来只对"当前指针位置"做径向排斥，划过去就是一串圆洞，离开后整块一起缩回，没有任何被劈开的形状。

- **轨迹推力**：`pointermove` 里按 9px 间距记录路径点（最多 24 个，保留 0.7s），每段就是一个"刀身"。粒子取「到各线段最近点」里最强的一段，方向 = 最近点→粒子，即**垂直于刀口**，于是点被劈向两侧。鼠标停住不动时最后一段退化成点，仍然是圆形压力点。
- **回位按"历史峰值"分化**：每点存 `pk`（曾被顶开的最大距离），`kOut = EASE_OUT * (1 - DEPTH * min(pk/20, 1))`，`pk` 每帧乘 0.998 缓慢衰减。用 `pk` 而不是当前位移非常关键——用当前位移的话，一回落 `depth` 就掉、系数立刻变快，刀口两秒就抹平了（实测 20px → 3.8px 只要 1 秒）。
- **实测曲线**（划完后 max 位移 / 位移>6px 的点数）：0ms 31.8/216、500ms 29.9/180、1s 26/140、2.5s 17/82、4s 11/40 —— 缺口从两侧收，中心留得最久。
- **dt 归一**：`f60 = dt * 60`（dt 夹在 0.004~0.05），系数 `EASE * f60`。不这么做的话 120Hz 屏上刀口合拢速度快一倍。

## 02:40 刀口改成「劈开式」（archive.js?v=35，提交 e5eab95）

用户反馈「不像是刀锋，刀锋痕迹中间厚两边薄，然后划过的时候粒子离开的间距变大」。这一轮试了四种模型，只有最后一种成立：

1. **径向推力（旧版 v20）**：`ff = (1-d/PR)^2 * PUSH`。问题是映射会折叠 —— 离刀线 1px 的点被推 48px、20px 的点只推 21px，前后交叉，视觉上是「揉皱的一片」，不是刀口。
2. **压到槽沿（v23）**：槽内的点全部压到边缘窄环。结果贴合处 5 个点挤进 12px，糊成实心疙瘩。**任何「清空一条槽」的推力都必然把内侧几排点挤在一起**，这条路不可行。
3. **删点成槽（v24/v26）**：`ratio = d / (CH_W*w)`，<1 就淡出。边界是干净的透镜形，但点一少就是「掉了一块」，不像刀切；淡化档还留下灰点，显得脏。
4. **刚性劈开（最终）**：`d < PLATEAU` 时 `disp = CUT_W*w` 恒定 —— 点整体平移，**点距一点不变、行仍是直行**；`d > PLATEAU` 再在 FALL(320) 内二次收回到 0（320px 上只压缩 5%，看不出）。于是刀线两侧各让开 18px、中间留 36px 的缝，边界整齐。

关键：**要留下一条整齐的缝，位移必须在缝内取常数（刚性），衰减放到很远处**。之前所有失败都源于「位移随距离连续变化」→ 要么折叠、要么挤压。

- 刀身剖面 `bladeW(sBack)`：刀尖(0)=0.45 → 30% 处=1 → BLADE(230px)=0。缝宽 = 2×CUT_W×w，所以中间厚两头收尖。
- **坑**：原来 `ptW` 还乘了线性时间衰减 `1-age/0.7`，导致最厚的那几段（离刀尖 70~150px，也就是最老的）权重只有 0.5，wmax 测出来 0.54，缝根本没张开。改成「只按寿命判死，不乘衰减」后 wmax=1。用 CDP 探针数 `ink<0.5` 的点数才发现的（21 → 48）。

- 实测：划动中 60fps、无报错；划完 0.5s 内恢复（沿用上一版 EASE_OUT 0.18 / DEPTH 0.3）。
- 参数都在 `createLogo()` 开头：`CUT_W 18 / PLATEAU 34 / FALL 320 / BLADE 230 / BLADE_HOT 0.30`。
